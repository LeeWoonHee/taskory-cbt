## 최종 판정

**FAIL**

핵심 회원·시험 조회와 간편 등록 데이터 흐름은 동작하지만, P0 명시 수용 기준인 모바일 메뉴 키보드 동작·포커스 관리에 높은 심각도의 결함이 있다. 또한 localStorage에서 생성된 시험 상세의 문서 제목이 시험명을 반영하지 않고, 반복 링크의 접근 가능한 이름과 데스크톱 표의 상태 배지 줄바꿈이 디자인 명세를 충족하지 않는다. 필수 `bun run build`는 코드 오류가 아니라 현재 실행 환경의 Turbopack 내부 포트 바인딩 제한으로 완료되지 않았으며, 동일 소스를 Webpack으로 빌드한 결과는 통과했다.

## 브라우저 시나리오

### 1. 회원 목록 검색·필터 — 건강도: 양호

1. 320px에서 `/admin/members` 진입
2. `회원 검색`에 `민준` 입력 후 Enter
3. `활성` 상태 선택
4. URL이 `?q=민준&status=ACTIVE`로 유지되고 결과가 김민준 1명으로 축소됨
5. 결과 요약, 카드 데이터, `필터 초기화` 확인

확인 사항:

- 이름·이메일·회원 번호 검색 계약과 대소문자 비구분 로직이 서비스에 구현되어 있다.
- 모바일은 표 대신 카드가 표시되며 320px 전역 가로 넘침이 없다.
- 상세 복귀 URL에 검색·필터 조건이 보존된다.

### 2. 회원 상세·상태 변경 — 건강도: 기능 양호 / 접근성 결함

1. 김민준 상세 진입
2. `회원 정지` 선택
3. 대화상자에서 대상, 영향, `활성 → 정지`, 선택 사유, 명확한 실행 동사 확인
4. 초기 포커스가 `취소`에 놓이는 것을 확인
5. 정지 실행 후 배지 `정지`, `활성으로 복구`, 성공 토스트 확인
6. 새로고침 후에도 정지 상태가 localStorage에서 복구됨

결함:

- Escape로 닫으면 포커스가 `회원 정지` 트리거가 아니라 `body`로 이동한다. 같은 공통 대화상자를 쓰는 간편 등록 이탈 확인에도 영향 가능성이 있다.

### 3. 시험 목록 검색·필터·파생 상태 — 건강도: 양호

1. 1440px에서 `/admin/exams` 진입
2. 초안/게시 예정/진행 중/종료/보관 분포와 고정 기준 시각 설명 확인
3. `security` 검색 후 `임시 저장` 필터 적용
4. `SECURITY-2026` 1건, URL 조건과 결과 요약 확인

확인 사항:

- 고정 시각 `2026.08.05 09:00` 서울 기준 상태가 결정론적으로 표시된다.
- 일정 없는 초안은 `일정 미설정`으로 표시된다.
- 넓은 표만 지역 수평 스크롤을 사용하고 페이지 전역 넘침은 없었다.

### 4. 간편 등록 유효성 — 건강도: 양호

1. 320px에서 간편 등록 진입
2. 기본값: 기타, 60분, 20문항, 60점, 비공개 확인
3. 빈 폼 제출 → 제목·코드 2건 오류 확인
4. 오류 요약으로 포커스 이동, 필드 링크와 `aria-invalid`/`aria-describedby` 연결 확인
5. `SECURITY-2026`, 4분, 201문항, 101점 제출 → 4건 오류 확인
6. 서비스 단위에서 시작보다 이른 종료 시간 오류 확인

제한:

- 연결된 Chrome 자동화 환경에서 `datetime-local` 값 주입이 반영되지 않아 날짜 역전의 시각 UI는 서비스 계약으로만 확인했다.
- 실제 네트워크 저장 실패 경로는 데모 서비스가 실패 주입 기능을 제공하지 않아 브라우저에서 재현하지 못했다.

### 5. 간편 등록 성공·복구 — 건강도: 기능 양호 / 메타데이터 결함

1. `QA 역전 날짜 시험`, `QA-AUG-0501`로 초안 저장
2. 생성 상세에서 입력값, 생성 ID, `DRAFT`, 성공 토스트 확인
3. 상세 새로고침 후 동일 시험 복구 확인
4. 목록으로 이동해 전체 16건, 최신순 첫 행의 동일 값 확인

결함:

- 생성 상세의 `h1`은 `QA 역전 날짜 시험`이지만 문서 제목은 `시험 상세 · 관리자`로 남는다.

### 6. 모바일 메뉴 키보드 흐름 — 건강도: 불량

1. 320px 회원 목록에서 `관리자 메뉴 열기` 선택
2. 초기 포커스가 시트 닫기 버튼으로 이동하는 것은 확인
3. Escape 입력 → 메뉴가 닫히지 않음
4. Tab 이동 → `회원 관리` → `시험 관리` → 배경의 `데모 초기화`로 포커스가 이탈
5. 메뉴 열린 동안 `body`의 `overflow`가 `visible`로 유지됨
6. 닫기 버튼 선택 후 포커스가 메뉴 열기 트리거가 아닌 `body`로 이동

이는 디자인 명세의 Escape 닫기, 포커스 트랩, 배경 스크롤 잠금, 닫힘 뒤 트리거 복귀를 모두 위반한다.

## 결함 목록

### QA-ADM-001 — 모바일 메뉴에 Escape·포커스 트랩·스크롤 잠금·포커스 복귀가 없음

- 심각도: **High**
- 영향: 키보드 및 보조 기술 사용자가 메뉴 맥락을 벗어나거나 메뉴를 예측 가능한 방식으로 닫을 수 없음
- 영향 파일: `src/components/admin/admin-navigation.tsx`
- 재현 절차:
  1. 320px에서 `/admin/members` 진입
  2. `관리자 메뉴 열기` 선택
  3. Escape 입력
  4. 닫기 버튼에서 Tab을 세 번 입력
  5. 닫기 버튼을 선택한 뒤 활성 요소 확인
- 기대:
  - Escape로 닫힘
  - 포커스가 시트 안에 유지됨
  - 배경 스크롤이 잠김
  - 닫힌 뒤 `관리자 메뉴 열기`로 복귀
- 실제:
  - Escape 후 메뉴가 유지됨
  - 세 번째 Tab에서 배경 `데모 초기화`로 이탈
  - `body` overflow가 `visible`
  - 닫힘 뒤 활성 요소가 `body`
- 수정 권고:
  - shadcn/ui `Sheet` 또는 Radix Dialog 기반 구현으로 교체
  - `aria-modal`, 포커스 스코프/트랩, Escape 처리, 배경 inert/스크롤 잠금 적용
  - 열기 트리거 ref를 보존하고 모든 닫힘 경로에서 포커스 복귀

### QA-ADM-002 — 공통 확인 대화상자 닫힘 후 트리거 포커스 복귀 실패

- 심각도: **Medium**
- 영향: 상태 변경 및 이탈 확인 후 키보드 사용자가 현재 위치를 잃음
- 영향 파일: `src/components/ui/alert-dialog.tsx`, `src/components/admin/member-detail.tsx`, `src/components/admin/exam-form.tsx`
- 재현 절차:
  1. 768px 회원 상세에서 `회원 정지` 선택
  2. 초기 포커스가 `취소`임을 확인
  3. Escape로 닫기
- 기대: `회원 정지` 트리거로 포커스 복귀
- 실제: 활성 요소가 `body`
- 수정 권고:
  - 열기 직전 `document.activeElement`를 안전하게 보존하고 닫힌 뒤 복귀
  - 가능하면 shadcn/Radix `AlertDialog`의 검증된 focus scope 사용
  - Escape, 취소, 배경 클릭, 실행 성공 모든 닫힘 경로를 회귀 테스트

### QA-ADM-003 — localStorage 생성 시험 상세의 문서 제목이 시험명을 반영하지 않음

- 심각도: **Medium**
- 영향: 화면 전환 알림, 탭 식별, 보조 기술의 페이지 맥락 전달 저하
- 영향 파일: `src/app/admin/exams/[examId]/page.tsx`, `src/components/admin/exam-detail.tsx`
- 재현 절차:
  1. 간편 등록으로 localStorage 시험 생성
  2. 생성 상세의 `h1`과 `document.title` 비교
  3. 새로고침 후 다시 비교
- 기대: `{시험명} · 시험 상세 · 관리자`
- 실제: `시험 상세 · 관리자`
- 원인: `generateMetadata`가 서버의 초기 데모 서비스만 조회해 브라우저 localStorage 시험을 알 수 없음
- 수정 권고:
  - P0 localStorage 데모에서는 hydration 후 `document.title`을 안전하게 동기화하는 클라이언트 보완 추가
  - 실데이터 전환 시 서버에서 동일 시험을 조회해 Metadata API로 단일화

### QA-ADM-004 — 반복 `상세 보기` 링크의 접근 가능한 이름이 대상별로 구분되지 않음

- 심각도: **Medium**
- 영향: 링크 목록이나 빠른 탐색에서 어느 회원/시험의 상세 링크인지 구분하기 어려움
- 영향 파일: `src/components/admin/members-list.tsx`, `src/components/admin/exams-list.tsx`
- 재현 절차:
  1. 회원 또는 시험 목록의 접근성 트리 확인
  2. 모든 행·카드 링크가 `상세 보기`로만 노출되는지 확인
- 기대: `김민준 회원 상세 보기`, `2026 정보보안 기본 역량 평가 시험 상세 보기` 등 대상 포함
- 실제: 모든 링크가 `상세 보기`
- 수정 권고: 시각 문구는 유지하되 대상명을 포함한 `aria-label` 또는 스크린 리더 전용 텍스트 추가

### QA-ADM-005 — 1440px 시험 표에서 상태 배지와 작업 문구가 여러 줄로 분리됨

- 심각도: **Low**
- 영향: 고밀도 데스크톱 표의 스캔 효율과 상태 배지 일관성 저하
- 영향 파일: `src/components/ui/badge.tsx`, `src/components/admin/exams-list.tsx`
- 재현 절차: 1440px에서 전체 시험 목록 확인
- 기대: 상태 배지와 `상세 보기`가 한 줄 유지
- 실제: `임시 저장`, 일부 머리글과 `상세 보기`가 두 줄로 갈라짐
- 수정 권고:
  - 배지와 작업 링크에 `whitespace-nowrap`
  - 상태·작업 열 최소 폭 또는 표의 최소 폭 재조정
  - 표 컨테이너의 지역 스크롤 정책은 유지

### QA-ADM-006 — 한쪽 일정만 있는 계약 오류를 `일정 미설정`으로 숨김

- 심각도: **Low**
- 영향: 상위 데이터 계약 오류를 정상 미설정 상태로 오인할 수 있음
- 영향 파일: `src/lib/admin-format.ts`, `src/components/admin/exams-list.tsx`, `src/components/admin/exam-detail.tsx`
- 재현 절차: `formatPeriod(validStart, null)` 호출
- 기대: 디자인 명세에 따라 `일정 정보 오류`와 오류 표시
- 실제: `일정 미설정`
- 수정 권고: 둘 다 `null`일 때만 `일정 미설정`, 한쪽만 있을 때 별도 오류 상태 반환

## 확인된 강점

- App Router의 페이지·레이아웃은 서버 컴포넌트 기본, 상호작용 영역만 클라이언트 경계로 분리되어 있다.
- 검색·필터 URL 계약과 상세 복귀 맥락이 일관된다.
- 데모 데이터는 회원/시험 수와 파생 상태가 기획 사양대로 결정론적이다.
- 위험 회원 상태 전이는 서비스 계층에서 허용 전이와 오래된 `fromStatus`를 검증한다.
- 등록 오류 요약, 필드 오류, 도움말, `aria-invalid`, `aria-describedby` 연결이 양호하다.
- 상태는 텍스트 배지로 표시되어 색상에만 의존하지 않는다.
- `prefers-reduced-motion` 대응과 Motion 축소 분기가 있다.
- 320/768/1440 주요 화면에서 전역 가로 넘침이 없었다.
- 브라우저 콘솔 error/warn이 없었다.

## 남은 위험과 미검증 범위

- `bun run build`의 Turbopack 경로는 실행 환경의 포트 바인딩 제한으로 완전 검증하지 못했다. Webpack 빌드 통과가 Turbopack 통과를 보장하지 않는다.
- 실제 저장 실패, 목록 조회 실패, 데이터 자체 없음, 401, 403은 데모 서비스에 실패/권한 주입 수단이 없어 동적 재현하지 못했다.
- 날짜 역전은 서비스 계약으로 확인했으나 브라우저의 `datetime-local` 자동화 제약으로 시각 오류 상태를 캡처하지 못했다.
- 375, 640, 1024px, 200%/400% 확대, 고대비 모드, 화면 회전은 별도로 실행하지 않았다.
- axe 및 실제 스크린 리더 자동/수동 검사는 수행하지 않았다. 따라서 WCAG 2.2 AA 전체 준수를 주장할 수 없다.
- 대비 수치는 도구로 계측하지 않았고 명세 색상과 시각 확인만 수행했다.
- 간편 등록의 브라우저 뒤로 가기 이탈 경고와 빠른 연속 실제 클릭은 별도 자동 재현하지 않았다. 서비스 중복 거부와 버튼 비활성 구현만 확인했다.
- `loading.tsx`가 없어 실제 비동기 백엔드 전환 시 목록 로딩 상태의 셸 유지·`aria-busy` 동작을 다시 검증해야 한다.

## 출시 전 권고 우선순위

1. QA-ADM-001 모바일 메뉴 접근성 결함을 먼저 수정한다.
2. QA-ADM-002 대화상자 포커스 복귀와 QA-ADM-004 반복 링크 이름을 수정하고 키보드 회귀 테스트를 추가한다.
3. QA-ADM-003 생성 시험 메타데이터를 localStorage 데모와 일치시킨다.
4. QA-ADM-005/006 시각·데이터 오류 표현을 정리한다.
5. Turbopack 포트 바인딩이 허용되는 CI/로컬 환경에서 원래 `bun run build`를 재실행한다.
6. 실패·권한·데이터 없음 상태 주입 테스트와 자동 접근성/E2E 테스트를 추가한다.
