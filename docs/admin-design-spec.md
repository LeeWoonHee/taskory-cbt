# 관리자 회원·시험 관리 UX/UI 명세

## 1. 문서 목적

이 문서는 `docs/admin-product-plan.md`의 P0 범위를 실제 화면으로 구현하기 위한 관리자 UX/UI 기준을 정의한다. 대상은 관리자 공통 셸, 회원 목록·상세, 시험 목록·상세, 시험 간편 등록이며, 데스크톱 중심의 고밀도 운영 경험과 320px 이상 모바일 환경을 함께 다룬다.

구현 시 별도 시각 결정을 최소화할 수 있도록 화면 구조, 반응형 전환, 컴포넌트 상태, 문구, 디자인 토큰, 미세 모션, 접근성, QA 기준을 명시한다. Tailwind CSS 레이아웃은 모든 화면에서 `flex`와 래핑 조합만 사용하며 `grid` 및 `grid-*` 유틸리티는 사용하지 않는다.

### 1.1 범위와 전제

- 운영 언어: 한국어
- 기준 시간대: `Asia/Seoul`
- 날짜·시간 형식: `YYYY.MM.DD HH:mm`
- P0 권한: 단일 `관리자`
- 기본 정렬: 회원은 가입일 최신순, 시험은 수정일 최신순
- 데모 변경: 현재 세션에만 유지될 수 있으며 새로고침 시 초기화 가능
- P0 간편 등록 결과: 항상 `DRAFT`
- P0에서 문항 편집·게시·시험 수정·페이지네이션은 제공하지 않음

### 1.2 경험 원칙

1. **찾기 우선**: 페이지 진입 직후 검색과 상태 필터가 보이고, 현재 조건과 결과 건수를 항상 확인할 수 있어야 한다.
2. **맥락 유지**: 상세에서 목록으로 돌아갈 때 검색어와 상태 필터를 유지한다.
3. **결과가 분명한 동사**: `확인` 대신 `회원 정지`, `탈퇴 처리`, `임시 저장`처럼 결과를 예측할 수 있는 레이블을 사용한다.
4. **안전한 변경**: 위험 작업은 대상, 영향, 복구 가능 여부를 확인한 뒤 실행한다. 실패하면 원래 상태와 입력값을 보존한다.
5. **상태를 색에 맡기지 않기**: 상태는 텍스트 배지, 아이콘 또는 보조 설명을 함께 사용한다.
6. **셸은 안정적으로, 콘텐츠만 갱신**: 로딩·필터링·오류 처리 중에도 내비게이션과 페이지 맥락은 유지한다.
7. **데모임을 숨기지 않기**: 전역 배지와 필요한 성공 메시지에서 비영속성 가능성을 명확히 알린다.

## 2. 정보 구조와 라우트

| 경로 | 화면 | 대표 행동 | 문서 제목 |
| --- | --- | --- | --- |
| `/admin` | 회원 관리로 이동 | 없음 | 해당 없음 |
| `/admin/members` | 회원 목록 | 검색, 상태 필터, 상세 진입 | `회원 관리 · 관리자` |
| `/admin/members/[memberId]` | 회원 상세 | 상태 변경 | `{회원명} · 회원 상세 · 관리자` |
| `/admin/exams` | 시험 목록 | 검색, 상태 필터, 간편 등록, 상세 진입 | `시험 관리 · 관리자` |
| `/admin/exams/new` | 시험 간편 등록 | 초안 저장, 취소 | `시험 간편 등록 · 관리자` |

### 2.1 내비게이션 계층

- 1차 내비게이션: `회원 관리`, `시험 관리`
- 2차 맥락: 페이지 제목과 뒤로 가기 또는 브레드크럼
- 주요 작업: 시험 목록의 `시험 간편 등록`
- 전역 상태: `데모 모드`, 현재 관리자

상세 화면의 상위 메뉴는 계속 활성 상태로 표시한다. 예를 들어 `/admin/exams/new`와 `/admin/exams/[examId]`에서는 `시험 관리`가 활성 상태다.

## 3. 공통 관리자 셸

### 3.1 대형 화면: 1024px 이상

화면은 왼쪽 사이드 내비게이션과 오른쪽 콘텐츠 영역을 가로 방향 `flex`로 구성한다.

- 사이드 내비게이션: 폭 240px, 화면 높이에 고정, 내부 세로 `flex`
- 콘텐츠 영역: `min-w-0 flex-1`, 최소 높이 화면 전체
- 상단 바: 높이 64px, 콘텐츠 영역 상단에 고정 가능, 좌우 `flex`
- 본문: 최대 폭 1440px, 좌우 패딩 32px, 상하 패딩 32px
- 페이지 헤더와 본문 사이: 24px
- 콘텐츠 카드 사이: 16~24px
- 표가 넓은 경우 전역 페이지가 아니라 표 컨테이너에만 수평 스크롤 허용

사이드 내비게이션 순서는 다음과 같다.

1. 서비스 워드마크 또는 로고, 접근 가능한 이름 `Taskory 관리자`
2. 주 내비게이션
3. 남는 공간
4. `데모 모드` 설명 링크 또는 보조 문구
5. 관리자 프로필 요약

상단 바에는 현재 섹션 이름을 중복해 크게 표시하지 않는다. 왼쪽에는 필요 시 브레드크럼, 오른쪽에는 `데모 모드` 배지와 관리자 표시를 둔다. 데모 배지는 사이드 영역과 상단 바 중 한 곳에만 항상 보이면 되며 중복 노출하지 않는다.

### 3.2 중형 화면: 640~1023px

- 사이드 내비게이션을 폭 72px의 아이콘형으로 축소하거나 상단 바 메뉴로 전환한다.
- 아이콘형을 사용할 때 각 항목은 툴팁과 접근 가능한 이름을 가진다.
- 본문 패딩은 24px, 콘텐츠 간격은 20px로 줄인다.
- 회원·시험 표는 핵심 열만 유지하고 보조 열은 숨긴다.
- 768px 전후에서도 검색, 필터, 주요 작업이 한 줄에 억지로 압축되지 않도록 `flex-wrap`을 허용한다.
- 폭이 부족하면 검색 입력은 한 줄 전체, 필터와 CTA는 다음 줄에 배치한다.

### 3.3 소형 화면: 640px 미만

- 상단 앱 바: 높이 56px, 좌우 패딩 16px
- 왼쪽: 메뉴 버튼과 서비스명
- 오른쪽: `데모` 축약 배지
- 메뉴 버튼은 shadcn/ui `Sheet`를 열며, 시트 폭은 `min(320px, calc(100vw - 40px))`
- 본문: 패딩 16px, 상단 20px, 하단 32px
- 표는 렌더링하지 않고 같은 데이터 계약을 사용하는 카드 목록으로 전환한다.
- 검색 입력은 전체 폭, 필터는 접이식 패널 또는 가로 스크롤 없는 줄바꿈 버튼 묶음으로 제공한다.
- 페이지 주요 작업은 헤더 아래 전체 폭 버튼 또는 하단 고정 작업 영역에 둔다. 두 위치에 동시에 중복하지 않는다.
- 하단 고정 작업 영역은 키보드가 열렸을 때 입력을 가리지 않아야 하며, 안전 영역에 `env(safe-area-inset-bottom)`을 반영한다.
- 320px에서 긴 이름·이메일·시험명이 컨테이너를 넓히지 않도록 부모에 `min-w-0`, 텍스트에 줄바꿈 또는 말줄임을 지정한다.

### 3.4 페이지 공통 헤더

목록 화면 헤더는 제목 영역과 주요 작업 영역을 `flex`로 구성한다.

- `h1`: 화면당 하나, 24~30px, 굵기 700
- 설명: `h1` 아래 4~8px, 중립 보조색, 최대 70자 권장
- 전체 건수: 제목 바로 뒤 배지보다 설명 문장 안에 `전체 24명`처럼 제공
- 주요 버튼: 대형 화면 오른쪽, 모바일에서는 제목 아래 전체 폭
- 상세 화면: `목록으로` 링크 → 요약 헤더 → 세부 섹션 순서
- 등록 화면: `시험 관리 / 간편 등록` 브레드크럼 → `h1` → 데모 안내

## 4. 전역 내비게이션 명세

### 4.1 내비게이션 항목

| 항목 | 아이콘 예시 | 경로 | 활성 조건 |
| --- | --- | --- | --- |
| 회원 관리 | `Users` | `/admin/members` | `/admin/members`로 시작 |
| 시험 관리 | `ClipboardList` | `/admin/exams` | `/admin/exams`로 시작 |

- 항목 높이: 최소 44px
- 아이콘: 20px, 장식용이면 `aria-hidden="true"`
- 텍스트: 14px, 기본 500, 활성 600
- 항목 사이: 4px
- 활성 상태: 연한 주색 배경 + 진한 주색 텍스트 + 굵기 변화
- 포커스 상태: 2px 외곽선과 2px 간격
- 마우스 오버: 120ms 안에 중립 배경만 변화
- 현재 항목에 `aria-current="page"` 적용

### 4.2 모바일 시트 내비게이션

- 시트 제목: `관리자 메뉴`
- 열릴 때 첫 내비게이션 항목 또는 닫기 버튼으로 포커스 이동
- 닫기 버튼의 접근 가능한 이름: `관리자 메뉴 닫기`
- Escape로 닫기, 닫힌 뒤 메뉴 버튼으로 포커스 복귀
- 항목 선택 후 경로가 바뀌면 시트를 닫는다.
- 배경 스크롤을 잠그고 시트 내부만 스크롤한다.

### 4.3 데모 모드 표시

배지 텍스트는 대형 화면에서 `데모 모드`, 모바일에서 `데모`로 표시한다. 배지 가까이에 다음 설명을 툴팁 또는 팝오버로 제공한다.

> 변경 내용은 현재 세션에만 유지되며 새로고침하면 초기화될 수 있습니다.

툴팁에만 핵심 제약을 숨기지 않는다. 시험 등록 화면과 변경 성공 메시지처럼 데이터 지속성을 오해하기 쉬운 지점에서는 같은 의미를 인라인으로 다시 알린다.

## 5. 회원 목록 `/admin/members`

### 5.1 화면 목적과 우선순위

관리자가 이름·이메일·회원 번호와 상태를 조합해 대상을 빠르게 찾고 상세로 이동하는 화면이다. 첫 진입 시 가입일 최신순으로 24명의 데모 회원을 표시한다.

### 5.2 데스크톱 구조

1. 페이지 헤더
   - `h1`: `회원 관리`
   - 설명: `전체 24명의 가입 정보와 이용 상태를 관리합니다.`
2. 검색·필터 카드
   - 검색 입력
   - 상태 필터
   - 조건 초기화
3. 결과 요약
   - 예: `상태: 활성 · 검색어: “민준” · 2명`
   - 정렬 안내: `가입일 최신순`
4. 회원 표

검색·필터 카드는 대형 화면에서 가로 `flex`, 중·소형에서 `flex-wrap` 또는 세로 `flex`로 전환한다.

### 5.3 검색

- 레이블: `회원 검색`
- 플레이스홀더: `이름, 이메일, 회원 번호 검색`
- 검색 아이콘은 장식용
- 입력값 지우기 버튼: 값이 있을 때만 표시, 접근 가능한 이름 `검색어 지우기`
- 동작: 300~500ms 디바운스 또는 명시적 `검색` 버튼 중 하나로 일관되게 구현
- Enter 제출 가능
- 쿼리 이름: `q`
- 앞뒤 공백 제거, 영문 대소문자 구분 없이 검색
- 입력 중 매 키 입력마다 라이브 영역을 과도하게 읽지 않고 결과 확정 후 건수만 알림

### 5.4 상태 필터

| 표시 | 값 | 배지/필터 의미 |
| --- | --- | --- |
| 전체 | 없음 | 모든 회원 |
| 활성 | `ACTIVE` | 로그인·응시 가능 |
| 정지 | `SUSPENDED` | 로그인·새 응시 불가 |
| 탈퇴 | `WITHDRAWN` | 읽기 전용 보존 레코드 |

대형 화면에서는 shadcn/ui `Tabs` 또는 단일 선택 버튼 묶음을 사용한다. 모바일에서 공간이 부족하면 `Select`로 바꿀 수 있지만, 선택값과 URL 계약은 동일하게 유지한다. 버튼 묶음은 `전체`를 포함해 단일 선택이며 선택 상태를 아이콘·배경·텍스트로 함께 표현한다.

### 5.5 데스크톱 표

표에는 접근 가능한 캡션 `가입일 최신순 회원 목록`을 제공한다.

| 열 | 정렬/너비 지침 | 표시 규칙 |
| --- | --- | --- |
| 회원 | 최소 160px | 이름 600, 회원 번호는 보조 텍스트 |
| 이메일 | 최소 220px | 한 줄 말줄임, 전체 값은 title이 아니라 상세에서 제공 |
| 상태 | 96px | 텍스트 배지 |
| 가입일 | 132px | `YYYY.MM.DD` |
| 최근 로그인 | 148px | 없으면 `로그인 기록 없음` |
| 응시 횟수 | 88px | `0회` 포함 숫자 정렬 |
| 작업 | 96px | `상세 보기` 링크 |

- 행 높이: 최소 64px
- 행 전체를 클릭 영역으로 만들더라도 실제 키보드 포커스 대상은 명시적 상세 링크로 제공한다.
- 행 클릭과 내부 링크가 이중으로 동작하지 않도록 이벤트 중첩을 피한다.
- 마우스 오버에서 중립 배경을 표시하되 포커스 스타일을 대체하지 않는다.
- 응시 횟수와 날짜에는 숫자 폭이 흔들리지 않도록 `tabular-nums` 사용을 권장한다.

### 5.6 모바일 카드

각 카드는 하나의 회원을 나타내며 다음 순서로 읽힌다.

1. 이름과 상태 배지
2. 이메일
3. 회원 번호
4. 가입일
5. 최근 로그인
6. 응시 횟수
7. `상세 보기`

카드 패딩 16px, 카드 간격 12px, 핵심 정보와 보조 정보 사이는 12px로 한다. 이름과 상태는 `flex-wrap`을 허용한다. 이메일은 복사 기능 없이 줄바꿈 가능하게 표시한다. 카드 전체에 숨겨진 링크를 덮지 말고 명시적 `상세 보기` 링크의 터치 영역을 최소 44px로 확보한다.

### 5.7 결과 요약과 초기화

- 조건 없음: `전체 24명 · 가입일 최신순`
- 필터만 적용: `활성 회원 16명 · 가입일 최신순`
- 검색과 필터 적용: `활성 · “민준” 검색 결과 2명`
- `필터 초기화`는 검색어와 상태를 모두 초기화한다.
- 한 조건만 지우는 동작은 검색 지우기와 필터 변경으로 제공한다.
- 결과 변경 알림은 `aria-live="polite"`로 짧게 `2명의 회원을 찾았습니다.`라고 전달한다.

## 6. 회원 상세 `/admin/members/[memberId]`

### 6.1 구조

1. `회원 목록으로` 링크
2. 요약 헤더
3. 기본 정보 카드
4. 이용 현황 카드
5. 최근 응시 내역 카드
6. 관리 작업 카드

대형 화면에서도 정보 카드를 고정된 열로 쪼개지 않고 `flex-wrap`으로 배치한다. 기본 정보와 이용 현황은 각각 `basis-[calc(50%-12px)] flex-1` 계열로 두되 최소 폭 320px 아래에서는 전체 폭으로 떨어진다. 관리 작업은 위험성을 고려해 일반 정보와 시각적으로 분리한다.

### 6.2 요약 헤더

- 회원 이름을 `h1`으로 사용
- 이메일, 회원 번호를 보조 정보로 표시
- 상태 배지는 이름 가까이에 배치
- ID는 `회원 ID` 레이블과 함께 전체 값을 표시하고 `ID 복사` 버튼 제공 가능
- 복사 성공: `회원 ID를 복사했습니다.`를 짧은 라이브 알림으로 제공

### 6.3 정보 항목

| 영역 | 항목 | 빈 값 문구 |
| --- | --- | --- |
| 기본 정보 | 이메일, 연락처, 회원 번호, 가입일 | 연락처는 `등록된 연락처 없음` |
| 이용 현황 | 최근 로그인, 응시 횟수, 합격 횟수 | `로그인 기록 없음`, 숫자는 `0회` |
| 최근 응시 | 시험명, 응시일, 점수, 결과 | 전체 영역에 `응시 이력이 없습니다.` |

데스크톱 최근 응시 내역은 표, 모바일은 최대 5개의 간결한 카드로 표시한다. 결과 배지는 `합격`, `불합격` 텍스트를 포함한다. 점수가 없을 수 있는 계약이 생기면 `채점 전`을 사용하고 `-`만 표시하지 않는다.

### 6.4 상태별 관리 작업

| 현재 상태 | 표시 작업 | 우선순위 |
| --- | --- | --- |
| `ACTIVE` | `회원 정지`, `탈퇴 처리` | 정지는 보조 위험, 탈퇴는 최종 위험 |
| `SUSPENDED` | `활성으로 복구`, `탈퇴 처리` | 복구는 기본/주요, 탈퇴는 위험 |
| `WITHDRAWN` | 없음 | `탈퇴 처리된 회원은 읽기 전용입니다.` 안내 |

회원 정지와 탈퇴 처리는 버튼 사이에 충분한 간격을 두고 한 번의 잘못된 탭으로 실행되지 않도록 한다. 실제 변경 전 확인 대화상자를 반드시 연다.

### 6.5 회원 정지 대화상자

- 제목: `{회원명} 회원을 정지할까요?`
- 설명: `정지하면 로그인과 새로운 시험 응시를 할 수 없습니다. 데모에서는 다시 활성 상태로 복구할 수 있습니다.`
- 현재/변경 상태: `활성 → 정지`
- 선택 입력 레이블: `정지 사유 (선택)`
- 플레이스홀더: `운영 참고용 사유를 입력하세요.`
- 취소 버튼: `취소`
- 실행 버튼: `{회원명} 회원 정지`
- 초기 포커스: `취소`
- 실행 중: `정지하는 중…`, 해당 버튼만 비활성화
- 성공: 대화상자를 닫고 상태 배지 갱신, `김민준 회원을 정지했습니다. 데모 변경은 새로고침 시 초기화될 수 있습니다.`
- 실패: 대화상자를 유지하고 `상태를 변경하지 못했습니다. 현재 상태는 활성으로 유지됩니다.`와 `다시 시도` 제공

### 6.6 활성 복구 대화상자

- 제목: `{회원명} 회원을 활성 상태로 복구할까요?`
- 설명: `복구하면 다시 로그인하고 시험에 응시할 수 있습니다.`
- 상태: `정지 → 활성`
- 실행 버튼: `활성으로 복구`
- 성공: `{회원명} 회원을 활성 상태로 복구했습니다.`

### 6.7 탈퇴 처리 대화상자

- 제목: `{회원명} 회원을 탈퇴 처리할까요?`
- 설명: `탈퇴 처리 후 P0에서는 복구할 수 없으며 회원 정보는 읽기 전용으로 보존됩니다. 실제 개인정보 처리 정책은 아직 확정되지 않았습니다.`
- 상태: `{활성 또는 정지} → 탈퇴`
- 확인 보조: 위험 아이콘과 `되돌릴 수 없음` 텍스트
- 실행 버튼: `탈퇴 처리`
- P0 데모에서 실제 기능을 노출할 경우 제품 계획의 법무·운영 미결정 위험을 인라인으로 알린다. 실서비스 전에는 비활성화하거나 별도 승인 정책을 확정해야 한다.

## 7. 시험 목록 `/admin/exams`

### 7.1 화면 목적과 구조

관리자가 시험명·코드와 운영 상태를 기준으로 시험을 찾고, 일정과 주요 지표를 확인하며 상세 또는 간편 등록으로 이동하는 화면이다.

1. 페이지 헤더
   - `h1`: `시험 관리`
   - 설명: `전체 15개의 시험 일정과 운영 상태를 관리합니다.`
   - 주요 버튼: `시험 간편 등록`
2. 검색·필터 카드
3. 상태 계산 설명
4. 결과 요약
5. 시험 표 또는 카드 목록

### 7.2 검색과 필터

- 검색 레이블: `시험 검색`
- 플레이스홀더: `시험명 또는 시험 코드 검색`
- 쿼리: `q`
- 상태 쿼리: `status`
- 상태 선택: `전체`, `임시 저장`, `게시 예정`, `진행 중`, `종료`, `보관`
- 결과 정렬: 수정일 최신순

상태 계산 설명은 정보 아이콘 버튼과 텍스트를 함께 제공한다.

> 게시 예정·진행 중·종료 상태는 게시 여부와 현재 서울 시간을 기준으로 자동 계산됩니다.

모바일에서는 툴팁에 긴 설명을 넣지 말고 접을 수 있는 인라인 도움말 또는 팝오버를 사용한다.

### 7.3 시험 상태 표시

| 값 | 화면 문구 | 의미 |
| --- | --- | --- |
| `DRAFT` | 임시 저장 | 아직 게시되지 않음 |
| `SCHEDULED` | 게시 예정 | 게시되었고 시작 전 |
| `OPEN` | 진행 중 | 현재 응시 기간 안 |
| `CLOSED` | 종료 | 종료 시각이 지남 |
| `ARCHIVED` | 보관 | 읽기 전용 보관 상태 |

상태 배지는 아이콘을 사용할 경우에도 텍스트를 생략하지 않는다. 기간 없는 초안은 `일정 미설정`으로 표시한다.

### 7.4 데스크톱 표

캡션은 `수정일 최신순 시험 목록`으로 한다.

| 열 | 너비 지침 | 표시 규칙 |
| --- | --- | --- |
| 시험 | 최소 240px | 시험명 600, 코드와 분류는 보조 텍스트 |
| 운영 상태 | 104px | 상태 배지 |
| 응시 기간 | 최소 210px | 시작과 종료를 두 줄로 표시 가능 |
| 제한 시간 | 96px | `{n}분` |
| 문항 수 | 88px | `{n}문항`, P0는 계획값 |
| 응시자 수 | 96px | `{n}명` |
| 수정일 | 148px | 날짜와 시간 |
| 작업 | 96px | `상세 보기` |

- 행 높이: 최소 72px
- 긴 시험명은 최대 두 줄, 그 이상 말줄임
- 일정이 모두 없으면 `일정 미설정`
- 한쪽 날짜만 있는 데이터는 유효하지 않은 계약 상태이므로 `일정 정보 오류`와 오류 아이콘을 표시하고 QA 결함으로 기록
- 숫자 열은 `tabular-nums` 권장

### 7.5 모바일 카드

표 대신 다음 순서의 카드 목록을 사용한다.

1. 시험명과 상태 배지
2. 시험 코드와 분류
3. 응시 기간
4. `문항 {n}개` · `제한 {n}분`
5. 응시자 수와 수정일
6. `상세 보기`

기본 카드에서 핵심 정보는 모두 읽을 수 있어야 한다. 보조 지표가 많아지면 `운영 정보 펼치기`를 제공할 수 있으나 시험명, 상태, 기간, 문항 수는 접지 않는다.

## 8. 시험 상세 `/admin/exams/[examId]`

### 8.1 구조

1. `시험 목록으로` 링크
2. 요약 헤더
3. 기본 정보 카드
4. 시험 설정 카드
5. 운영 정보 카드
6. 문항 안내 카드

### 8.2 요약 헤더

- `h1`: 시험명
- 상태 배지: 제목 옆 또는 다음 줄
- 시험 코드와 분류: 보조 정보
- 설명: 최대 500자, 원문 줄바꿈 보존, HTML 렌더링 금지
- ID: 전체 값과 `시험 ID 복사` 버튼 제공 가능

### 8.3 상세 필드

| 카드 | 필드 | 표현 |
| --- | --- | --- |
| 기본 정보 | 시험명, 코드, 설명, 분류 | 설명 없음은 `등록된 설명 없음` |
| 시험 설정 | 제한 시간, 계획 문항 수, 합격 점수, 공개 범위, 응시 기간 | 단위 포함 |
| 운영 정보 | 상태, 응시자 수, 생성일, 수정일 | 서울 시간 표시 |
| 문항 | 계획 문항 수 | 안내 상태 |

공개 범위 문구는 `비공개`, `링크 공개`, `전체 공개`를 사용한다. 응시 기간이 없으면 `일정 미설정`을 사용한다.

문항 안내 카드:

- 제목: `문항`
- 본문: `문항 편집은 다음 단계에서 제공됩니다.`
- 보조: `현재 계획 문항 수는 20개입니다.`
- 비활성 버튼을 의미 없이 두지 않는다. P1 기능을 예고할 필요가 있으면 텍스트 안내만 사용한다.

P0에는 수정·게시·종료·보관 버튼을 노출하지 않는다. 동작하지 않는 버튼을 미리 보여 주지 않는다.

## 9. 시험 간편 등록 `/admin/exams/new`

### 9.1 화면 구조

단일 페이지 폼이며 최대 읽기 폭은 880px로 제한한다.

1. 브레드크럼과 페이지 헤더
2. 데모 모드 인라인 안내
3. 오류 요약
4. `기본 정보` 섹션
5. `운영 설정` 섹션
6. 저장·취소 작업 영역

대형 화면에서도 입력 필드를 지나치게 가로로 늘리지 않는다. 짧은 수치 입력은 `flex-wrap` 행으로 묶고 각 필드에 최소 폭을 주며, 모바일에서는 세로로 쌓는다.

데모 안내 문구:

> 간편 등록한 시험은 임시 저장 상태로 생성됩니다. 데모 변경은 현재 세션에만 유지되며 새로고침하면 초기화될 수 있습니다.

### 9.2 기본 정보 필드

| 필드 | 컴포넌트 | 레이블/설명 | 상태 |
| --- | --- | --- | --- |
| 시험명 | `Input` | `시험명 (필수)`, 1~100자 | 글자 수는 오류 근처 또는 필요 시 표시 |
| 시험 코드 | `Input` | `시험 코드 (필수)`, `영문 대문자, 숫자, 하이픈 3~20자` | 입력 시 대문자 정규화 가능 |
| 분류 | `Select` | `분류 (필수)` | 기본 `기타`; 직무/자격/교육/기타 |
| 설명 | `Textarea` | `설명 (선택)` | 최대 500자, `123/500` 표시 |

시험 코드를 자동 대문자화하면 화면 값과 제출 값이 즉시 일치해야 하며 커서 위치를 방해하지 않아야 한다. 자동 제안값을 사용할 경우 사용자가 편집할 수 있고 제안값임을 설명한다.

### 9.3 운영 설정 필드

| 필드 | 컴포넌트 | 기본값 | 도움말 |
| --- | --- | --- | --- |
| 제한 시간 | 숫자 `Input` | 60 | `5~300분` |
| 계획 문항 수 | 숫자 `Input` | 20 | `1~200개, P0에서는 계획값` |
| 합격 점수 | 숫자 `Input` | 60 | `0~100점` |
| 공개 범위 | `Select` 또는 `RadioGroup` | 비공개 | `초안 저장 후에도 게시되지 않습니다.` |
| 응시 시작 | 날짜·시간 입력 | 비어 있음 | 서울 시간 |
| 응시 종료 | 날짜·시간 입력 | 비어 있음 | 시작보다 늦어야 함 |

응시 시작과 종료는 둘 다 입력하거나 둘 다 비워야 한다. 대형 화면에서는 같은 `flex` 행에 두되 각 입력의 레이블을 유지한다. 모바일에서는 시작 다음 종료 순으로 세로 배치한다. 브라우저 입력의 시간대가 모호해지지 않도록 그룹 설명에 `대한민국 표준시(서울)`를 표시한다.

### 9.4 작업 영역

- 주 버튼: `임시 저장`
- 보조 버튼: `취소`
- 대형 화면: 섹션 아래 오른쪽 정렬
- 모바일: 하단 고정 또는 폼 마지막에 전체 폭, `임시 저장`이 먼저 시각적으로 강조
- 저장 중: `저장하는 중…`, 중복 클릭 금지
- 취소: 변경값이 없으면 시험 목록으로 즉시 이동
- 변경값이 있으면 이탈 확인 대화상자 표시

### 9.5 클라이언트 검증 문구

| 조건 | 필드 오류 문구 |
| --- | --- |
| 시험명 없음 | `시험명을 입력해 주세요.` |
| 시험명 100자 초과 | `시험명은 100자 이하로 입력해 주세요.` |
| 코드 없음 | `시험 코드를 입력해 주세요.` |
| 코드 형식 오류 | `영문 대문자, 숫자, 하이픈을 사용해 3~20자로 입력해 주세요.` |
| 코드 중복 | `이미 사용 중인 시험 코드입니다.` |
| 분류 없음 | `분류를 선택해 주세요.` |
| 설명 500자 초과 | `설명은 500자 이하로 입력해 주세요.` |
| 제한 시간 범위 | `제한 시간은 5~300분으로 입력해 주세요.` |
| 문항 수 범위 | `계획 문항 수는 1~200개로 입력해 주세요.` |
| 합격 점수 범위 | `합격 점수는 0~100점으로 입력해 주세요.` |
| 날짜 한쪽만 입력 | `응시 시작과 종료를 모두 입력해 주세요.` |
| 날짜 역전 | `응시 종료는 시작보다 늦어야 합니다.` |

오류는 레이블 아래 입력과 가까운 곳에 표시한다. 입력에 `aria-invalid="true"`, 오류 ID를 `aria-describedby`로 연결한다. 도움말과 오류가 함께 있으면 두 ID를 모두 연결한다.

### 9.6 오류 요약

제출 시 오류가 하나 이상이면 폼 상단에 다음 구조로 표시한다.

- 제목: `입력 내용을 확인해 주세요.`
- 설명: `3개의 항목을 수정해야 합니다.`
- 목록: `시험명: 시험명을 입력해 주세요.`와 같이 각 필드로 이동하는 링크
- 컨테이너: `role="alert"`를 무조건 중복 적용하지 않고 제출 결과 시 한 번만 발표되도록 설계
- 제출 후 오류 요약 또는 첫 오류 필드로 포커스를 이동한다. 권장 기본은 오류 요약 포커스 후 링크로 개별 필드 이동이다.
- 사용자가 입력 중일 때 자동 포커스를 반복해서 이동하지 않는다.

### 9.7 저장 결과

성공 시 새 시험 상세로 이동하고 다음 메시지를 제공한다.

> 임시 시험이 저장되었습니다. 데모 변경은 새로고침하면 초기화될 수 있습니다.

목록으로 돌아가면 수정일 최신순 첫 결과에 새 시험이 표시되어야 한다.

알 수 없는 저장 실패:

- 입력값 유지
- 전역 오류: `시험을 저장하지 못했습니다. 입력 내용은 유지되었습니다.`
- 보조: `중복 생성 여부를 확인한 뒤 다시 시도해 주세요.`
- 버튼: `다시 시도`
- 내부 오류, 스택, SQL, 민감 정보 노출 금지

### 9.8 이탈 확인 대화상자

- 제목: `작성 중인 내용을 나갈까요?`
- 설명: `저장하지 않은 입력 내용이 사라집니다.`
- 안전 버튼: `계속 작성`
- 위험 버튼: `저장하지 않고 나가기`
- 초기 포커스: `계속 작성`
- 브라우저 뒤로 가기와 내부 링크 이동에 동일한 의도를 적용한다.
- 브라우저 탭 닫기·새로고침은 가능한 범위에서 기본 `beforeunload` 경고를 사용하되 커스텀 문구 노출을 보장하지 않는다.

## 10. 상태 화면과 피드백

### 10.1 로딩

- 관리자 셸과 내비게이션은 유지하고 데이터 영역만 로딩 처리
- 표 스켈레톤은 실제 열 수와 유사한 헤더와 5~8개 행
- 모바일 카드 스켈레톤은 실제 카드 정보 계층과 유사하게 4~6개
- 로딩 영역에 `aria-busy="true"`
- 스켈레톤 자체는 스크린 리더에서 숨기고 별도 문구 `회원 목록을 불러오는 중입니다.` 제공
- 펄스 애니메이션은 저강도, `prefers-reduced-motion`에서는 정적 표시
- 검색 결과 갱신 중 기존 결과를 전부 지우지 않고 진행 상태를 검색 영역 가까이에 표시할 수 있다.

### 10.2 데이터 자체가 없음

회원:

- 제목: `등록된 회원이 없습니다.`
- 설명: `회원 데이터가 추가되면 이곳에서 조회할 수 있습니다.`
- P0에는 회원 등록 CTA를 제공하지 않음
- 보조 행동: `새로고침`

시험:

- 제목: `등록된 시험이 없습니다.`
- 설명: `첫 시험을 임시 저장 상태로 만들어 보세요.`
- 주요 행동: `시험 간편 등록`

빈 화면은 아이콘, 제목, 설명, 행동 순으로 배치하며 장식 아이콘은 보조 기술에서 숨긴다.

### 10.3 필터 결과 없음

회원:

- 제목: `조건에 맞는 회원이 없습니다.`
- 설명: `검색어나 상태 조건을 바꿔 보세요.`
- 행동: `필터 초기화`

시험:

- 제목: `조건에 맞는 시험이 없습니다.`
- 설명: `검색어나 운영 상태 조건을 바꿔 보세요.`
- 행동: `필터 초기화`

현재 검색어와 상태 조건을 요약해 전체 데이터 없음과 구분한다.

### 10.4 목록 조회 실패

- 제목: `{회원 또는 시험} 목록을 불러오지 못했습니다.`
- 설명: `잠시 후 다시 시도해 주세요.`
- 행동: `다시 시도`
- 보조 행동: 다른 주 내비게이션으로 이동 가능
- 오류 원인, 요청 URL, 내부 식별자는 일반 사용자에게 노출하지 않음

### 10.5 상세 찾을 수 없음

- 제목: `{회원 또는 시험} 정보를 찾을 수 없습니다.`
- 설명: `삭제되었거나 잘못된 주소일 수 있습니다.`
- 주요 행동: `{회원 또는 시험} 목록으로`
- 관리자 셸 안에서 표시하며 잘못된 ID를 제목에 그대로 노출하지 않는다.

### 10.6 401과 403

401:

- 제목: `로그인이 필요합니다.`
- 설명: `관리자 화면을 보려면 로그인해 주세요.`
- 행동: `로그인으로 이동`

403:

- 제목: `접근 권한이 없습니다.`
- 설명: `이 기능이 필요하면 관리자에게 문의해 주세요.`
- 행동: `이전 화면으로` 또는 권한 있는 안전한 시작 화면

P0 데모에는 인증이 구현되지 않았음을 전역 데모 설명에 명시하며 실제 데이터가 권한 부족 응답 본문에 포함되지 않도록 후속 구현에서 검증한다.

### 10.7 예기치 않은 오류

- `/admin` 범위 오류 경계에서 셸 또는 최소한의 복귀 경로 유지
- 제목: `문제가 발생했습니다.`
- 설명: `요청을 처리하지 못했습니다. 다시 시도해 주세요.`
- 오류 식별자: 지원 문의가 필요한 경우에만 `오류 번호 {id}`
- 행동: `다시 시도`, `회원 관리로 이동`

### 10.8 토스트와 라이브 메시지

- 성공 토스트: 4~6초, 자동 닫힘 전에도 닫기 버튼 제공
- 오류 토스트: 자동 닫힘을 길게 하거나 사용자가 닫도록 함
- 토스트만으로 필수 정보를 전달하지 않고 화면 상태도 즉시 갱신
- 성공: `aria-live="polite"`
- 즉시 대응이 필요한 저장 실패: 적절한 인라인 오류와 함께 알림
- 동일 메시지가 빠르게 반복되지 않도록 중복 억제

## 11. 대화상자 공통 규칙

shadcn/ui `AlertDialog`는 상태 변경·이탈처럼 확인이 필요한 작업에 사용하고, 일반 정보 표시는 `Dialog` 또는 인라인 카드로 처리한다.

- 제목과 설명을 프로그램적으로 연결
- 배경 포커스 이동 차단과 포커스 트랩
- Escape 닫기 허용. 제출 진행 중에는 중복 실행을 막되 사용자를 이유 없이 가두지 않는다.
- 닫힌 뒤 원래 트리거로 포커스 복귀
- 모바일 폭: 좌우 16px 여백, 최대 폭 448px
- 버튼: 모바일에서 세로 배치 가능, 안전한 동작이 키보드 읽기 순서상 먼저
- 위험 버튼은 진한 빨강 배경과 명확한 동사 사용
- 상태 전이를 `현재 → 변경` 형태로 텍스트 표시
- 실행 중 버튼 너비가 바뀌지 않도록 최소 폭 유지
- 실패 시 대화상자를 닫지 않고 대상과 입력을 보존

## 12. 디자인 토큰

### 12.1 색상

기본은 중립색과 파랑 주색을 사용한다. 아래 값은 Tailwind 기본 팔레트 기준 권장안이며 실제 테마 변수로 매핑할 수 있다.

| 용도 | 권장 색 | 사용 |
| --- | --- | --- |
| 앱 배경 | `zinc-50` | 전체 관리자 배경 |
| 카드/표면 | `white` | 카드, 표, 대화상자 |
| 기본 텍스트 | `zinc-950` | 제목, 본문 |
| 보조 텍스트 | `zinc-600` | 설명, 메타데이터 |
| 약한 경계 | `zinc-200` | 카드 구분 |
| 입력 경계 | `zinc-500` | 비텍스트 UI 3:1 대비가 필요한 입력 외곽 |
| 주색 | `blue-700` | 주요 버튼, 링크 |
| 주색 호버 | `blue-800` | 주요 버튼 호버 |
| 주색 약한 배경 | `blue-50` | 활성 내비게이션 |
| 포커스 | `blue-600` | 포커스 링 |
| 위험 | `red-700` | 위험 버튼, 오류 텍스트 |
| 위험 호버 | `red-800` | 위험 버튼 호버 |

상태 배지:

| 상태 | 배경 | 텍스트 | 보조 아이콘 |
| --- | --- | --- | --- |
| 활성/진행 중 | `emerald-50` | `emerald-800` | 원 또는 체크 |
| 정지/게시 예정 | `amber-50` | `amber-900` | 일시 정지 또는 시계 |
| 탈퇴/보관 | `zinc-100` | `zinc-700` | 보관 또는 금지 |
| 임시 저장 | `blue-50` | `blue-800` | 문서 |
| 종료 | `slate-100` | `slate-800` | 완료 |
| 오류/불합격 | `red-50` | `red-800` | 경고 |

색상 조합은 실제 구현 후 대비 도구로 확인한다. 작은 본문 텍스트는 최소 4.5:1, 24px 이상 또는 18.66px 굵은 큰 텍스트는 3:1, 입력 경계·아이콘·포커스 등 UI 요소는 인접 색과 3:1 이상이어야 한다.

### 12.2 타이포그래피

시스템 한글 글꼴 스택 또는 프로젝트 기본 `Geist`와 적절한 한국어 대체 글꼴을 사용한다.

| 역할 | 크기/행간 | 굵기 |
| --- | --- | --- |
| 페이지 제목 | 30/38px 대형, 24/32px 모바일 | 700 |
| 상세/섹션 제목 | 20/28px | 650~700 |
| 카드 제목 | 16/24px | 600 |
| 본문 | 14/22px 또는 16/24px | 400 |
| 표 헤더 | 12/18px 또는 13/20px | 600 |
| 보조 텍스트 | 13/20px | 400 |
| 버튼/입력 | 14/20px | 500~600 |
| 배지 | 12/18px | 600 |

- 본문 기본은 14px 이상, 모바일 폼 입력은 브라우저 자동 확대 방지를 위해 16px 권장
- 긴 한국어 문장은 단어 단위 줄바꿈을 우선하며 의미 없는 자간 축소 금지
- 숫자 열과 날짜에는 `tabular-nums`
- 모두 대문자로 된 영문 레이블은 사용하지 않음

### 12.3 간격과 크기

4px 기준 간격 체계를 사용한다.

| 토큰 | 값 | 대표 사용 |
| --- | --- | --- |
| 1 | 4px | 아이콘과 짧은 텍스트 |
| 2 | 8px | 레이블과 입력, 제목과 설명 |
| 3 | 12px | 카드 내부 작은 그룹 |
| 4 | 16px | 모바일 패딩, 카드 기본 간격 |
| 5 | 20px | 중형 화면 간격 |
| 6 | 24px | 카드 패딩, 섹션 간격 |
| 8 | 32px | 대형 본문 패딩, 큰 섹션 간격 |
| 10 | 40px | 페이지 그룹 분리 |

- 버튼/입력 기본 높이: 40px
- 터치 대상: 최소 44×44px
- 주요 모바일 버튼: 최소 48px 높이
- 카드 모서리: 12px
- 입력/버튼 모서리: 8px
- 배지: 완전한 pill 또는 6px 모서리 중 하나로 일관
- 카드 그림자: 매우 약한 `shadow-sm`, 경계를 주 구분 수단으로 사용

### 12.4 아이콘

- 기본 16~20px, 빈 화면 장식 32~40px
- 아이콘 단독 버튼은 `aria-label`과 시각적 툴팁 제공
- 텍스트 버튼 안 아이콘은 장식용 처리 가능
- 상태 아이콘은 텍스트와 함께 사용
- 위험 경고는 삼각형, 정보는 원형 `i`, 성공은 체크처럼 익숙한 형태 사용

## 13. 컴포넌트 명세

### 13.1 Button

- 변형: `primary`, `secondary`, `outline`, `ghost`, `destructive`, `link`
- 한 영역의 주요 버튼은 원칙적으로 하나
- 비활성 상태는 대비를 지나치게 낮추지 않고 `disabled` 의미를 프로그램적으로 제공
- 로딩 상태는 스피너 + 진행 동사, 너비 유지
- 아이콘만 쓰는 버튼은 최소 44px 터치 영역

### 13.2 Input, Textarea, Select

- 항상 보이는 레이블 제공, 플레이스홀더를 레이블로 대체 금지
- 필수 여부를 `(필수)`로 텍스트 표시
- 도움말 → 입력 → 오류 순서
- 기본, 호버, 포커스, 입력됨, 비활성, 오류 상태 정의
- 포커스 링은 잘리지 않아야 함
- 오류는 색상 외에 아이콘과 문구 사용
- `Select`는 키보드 방향키와 Escape 동작을 지원

### 13.3 Badge

- 짧은 상태 명사 사용
- 한 줄 유지, 최소 높이 24px
- 목록과 상세에서 동일 상태는 동일한 문구·색·아이콘 사용
- 필터 선택 상태와 데이터 상태 배지를 혼동하지 않도록 필터는 버튼형, 데이터 상태는 읽기 전용 배지형으로 구분

### 13.4 Table

- shadcn/ui `Table` 우선 사용
- 캡션 또는 바로 앞 제목으로 목적 제공
- 열 머리글은 `scope="col"`
- 표 컨테이너에만 `overflow-x-auto`
- 고정 헤더를 사용할 경우 확대·키보드 포커스를 가리지 않는지 검증
- 모바일에서는 CSS로 표 구조만 시각적으로 바꾸지 말고 의미 있는 카드 마크업을 별도로 렌더링

### 13.5 Card

- 배경 `white`, 1px 경계, 12px 모서리
- 모바일 패딩 16px, 대형 20~24px
- 카드 안 카드 중첩을 최소화
- 정보 목록은 `dl`, `dt`, `dd` 사용을 권장
- 카드 전체 클릭보다 명시적 링크와 버튼 우선

### 13.6 EmptyState와 ErrorState

공통 구조를 재사용한다.

- 아이콘
- 제목
- 설명
- 주요 행동
- 선택적 보조 행동

빈 상태와 오류 상태는 아이콘 색, 제목, 행동 레이블만 바꿔 같은 레이아웃을 유지하되 의미는 명확히 구분한다.

### 13.7 Toast

- 성공, 오류, 정보 변형
- 제목은 한 문장, 필요 시 짧은 설명
- 닫기 버튼 제공
- 화면 모서리에서 콘텐츠를 가리지 않음
- 모바일에서는 좌우 16px, 하단 고정 작업 영역 위에 표시

## 14. 미세 모션

Motion 사용은 방향과 상태 변화를 이해시키는 범위로 제한한다.

| 대상 | 효과 | 시간 | 이징 |
| --- | --- | --- | --- |
| 모바일 내비게이션 | 오른쪽/왼쪽 방향 슬라이드 + 배경 페이드 | 180~220ms | ease-out |
| 대화상자 | 0.98→1 스케일 + 페이드 | 140~180ms | ease-out |
| 토스트 | 8px 이동 + 페이드 | 160~200ms | ease-out |
| 필터 결과 | 결과 영역 약한 페이드 | 120~160ms | ease-out |
| 상태 배지 변경 | 짧은 색/투명도 전환 | 120ms | linear/ease-out |
| 아코디언 | 높이·투명도 | 160~200ms | ease-out |

- 목록 항목을 연속으로 길게 등장시키는 스태거 효과는 사용하지 않는다.
- 테이블 행 재정렬 시 큰 이동 애니메이션을 사용하지 않는다.
- 저장·상태 변경 완료는 토스트와 텍스트 갱신이 주 피드백이며 애니메이션에 의존하지 않는다.
- `prefers-reduced-motion: reduce`에서는 이동·스케일을 제거하고 즉시 전환 또는 80ms 이하 페이드만 허용한다.
- 애니메이션 중에도 포커스 대상 위치와 읽기 순서가 안정적이어야 한다.

## 15. 접근성과 대비

### 15.1 키보드와 포커스

- 건너뛰기 링크 `본문으로 건너뛰기`를 첫 포커스 대상으로 제공
- 포커스 순서: 전역 내비게이션 → 페이지 헤더 작업 → 검색/필터 → 결과 → 페이지 작업
- `Tab`으로 모든 링크, 버튼, 입력, 필터, 행 상세 진입 가능
- 포커스 링: 최소 2px, 주변 색과 3:1 이상, `outline: none` 단독 사용 금지
- 검색 결과 갱신 후 포커스를 목록 시작으로 강제 이동하지 않음
- 라우트 이동 후 페이지 `h1` 또는 본문 시작점 알림 전략을 검증
- 대화상자와 시트 닫힘 뒤 트리거로 포커스 복귀

### 15.2 의미 구조

- 화면당 하나의 `h1`, 제목 단계 건너뛰기 최소화
- 주 내비게이션에 `aria-label="관리자 주 메뉴"`
- 본문에 고유 `id`와 `main`
- 정보 쌍은 `dl/dt/dd`, 실제 행·열 데이터는 `table`
- 아이콘 장식은 `aria-hidden="true"`
- 반복되는 `상세 보기` 링크에는 접근 가능한 이름을 `김민준 회원 상세 보기`처럼 확장
- 현재 메뉴는 `aria-current="page"`

### 15.3 폼과 오류

- 모든 입력에 보이는 레이블
- 필수 여부 텍스트 표기와 HTML 필수 속성/서버 검증 병행
- 도움말과 오류를 `aria-describedby`로 연결
- 오류 입력에 `aria-invalid`
- 오류 요약 링크가 정확한 입력으로 이동
- 같은 오류를 라이브 영역, 토스트, 필드에서 동시에 반복 낭독하지 않도록 발표 우선순위 조정
- 날짜·시간 입력에 시간대와 예시 제공

### 15.4 라이브 영역

- 검색 결과 건수: `polite`
- 저장 성공·상태 변경 성공: `polite`
- 저장 실패: 인라인 오류에 포커스 또는 상황에 따라 `assertive`
- 로딩 시작과 끝을 매번 과도하게 알리지 않음
- 시각적으로 갱신된 상태 배지에도 텍스트가 변경되어야 함

### 15.5 확대, 고대비, 터치

- 200% 확대에서 전역 가로 스크롤 없이 핵심 흐름 완료
- 400% 확대에서는 모바일형 레이아웃으로 자연스럽게 재배치
- Windows 고대비 모드에서 경계·포커스·상태가 유지되는지 확인
- 터치 대상 최소 44×44px, 인접 위험 작업 사이 8px 이상
- hover에만 존재하는 정보 금지
- 화면 방향 변경에도 입력값과 대화상자 상태 보존

## 16. Tailwind CSS 구현 힌트

모든 예시는 `flex` 기반이다. 프로젝트 규칙에 따라 `grid`, `inline-grid`, `display: grid` 및 Tailwind `grid-*` 유틸리티를 사용하지 않는다.

### 16.1 관리자 셸

```tsx
<div className="flex min-h-dvh bg-zinc-50 text-zinc-950">

      {/* 모바일 메뉴 / 전역 상태 */}
    </header>
    <main id="main-content" className="min-w-0 flex-1 px-4 py-5 sm:px-6 lg:px-8 lg:py-8">
      <div className="mx-auto flex w-full max-w-[1440px] flex-col gap-6">
        {/* 페이지 */}
      </div>
    </main>
  </div>
</div>
```

### 16.2 페이지 헤더

```tsx
<div className="flex flex-col gap-4 sm:flex-row sm:items-start sm:justify-between">
```

```tsx
<dl className="flex flex-col divide-y">
  <div className="flex flex-col gap-1 py-3 sm:flex-row sm:items-start sm:justify-between sm:gap-6">
    <dt className="shrink-0 text-sm text-zinc-600">최근 로그인</dt>
```

### 16.6 데스크톱 표와 모바일 카드 전환

```tsx

  <Table>{/* 데스크톱 데이터 */}</Table>
</div>
<ul className="flex flex-col gap-3 md:hidden">
  {/* 동일 DTO를 사용하는 모바일 카드 */}

```

### 16.7 폼 수치 필드 묶음

```tsx
<div className="flex flex-wrap gap-4">
  <div className="min-w-52 basis-full sm:flex-1">{/* 제한 시간 */}</div>
  <div className="min-w-52 basis-full sm:flex-1">{/* 계획 문항 수 */}</div>
  <div className="min-w-52 basis-full sm:flex-1">{/* 합격 점수 */}</div>
</div>
```

### 16.8 상태·접근성 유틸리티

- 긴 flex 자식: `min-w-0`
- 고정 영역: `shrink-0`
- 숫자: `tabular-nums`
- 키보드 포커스: `focus-visible:outline-none focus-visible:ring-2 focus-visible:ring-blue-600 focus-visible:ring-offset-2`
- 줄바꿈: 이메일·ID는 `break-all` 또는 적절한 `overflow-wrap`, 일반 제목은 `break-words`
- 모션 축소: `motion-reduce:transition-none motion-reduce:animate-none`
- 터치 크기: `min-h-11 min-w-11`
- 전역 수평 넘침을 숨겨 결함을 감추지 말고 원인 요소에 `min-w-0`, 래핑, 지역 스크롤 적용

- [ ] 본문 텍스트 4.5:1, 큰 텍스트와 UI 요소 3:1 이상을 측정한다.
- [ ] 상태가 텍스트 없이 색상으로만 전달되지 않는다.
- [ ] 표 캡션, 열 머리글, 정보 목록 의미 구조를 검사한다.
- [ ] 입력 레이블·도움말·오류가 프로그램적으로 연결된다.
- [ ] 라이브 영역이 결과와 성공·실패를 중복 없이 알린다.
- [ ] 시트·대화상자의 포커스 트랩과 트리거 복귀를 확인한다.
- [ ] `prefers-reduced-motion`, 고대비, 화면 방향 변경에서 기능이 유지된다.

### 18.8 권장 검증 도구와 순서

1. `bun run lint`로 정적 규칙과 접근성 경고 확인
2. `bun run build`로 라우트·Server/Client 경계 확인
3. 브라우저 개발자 도구의 320/375/768/1024/1440px 뷰포트 점검
4. 키보드 단독 탐색과 스크린 리더 기본 흐름 점검
5. axe 또는 동등 도구로 자동 접근성 검사
6. 대비 검사기로 텍스트, 입력 경계, 포커스, 상태 배지 측정
7. 네트워크 지연·오프라인·저장 실패를 강제로 만들어 상태 화면 확인
8. `prefers-reduced-motion`, 200%·400% 확대, 고대비 모드 수동 확인

### 19.2 후속 결정이 필요한 위험

| 일정 경계 | 서울 시간 표기 | 시작/종료 포함 여부와 서버 기준 시각 |
| 시험 코드 | 형식·중복 오류만 명세 | 생성 주체와 충돌 처리 |
